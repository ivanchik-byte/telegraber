# telegraber

Автономный self-hosted инструмент в Docker для скачивания и архивации медиафайлов (видео, фото, документы, альбомы) из любых Telegram-каналов и чатов, включая каналы с включенным запретом на сохранение и пересылку контента (`noforwards` / `protect_content`).

Управление полностью реализовано через Telegram: вы общаетесь со своим ботом-контроллером, настраиваете сессию через диалог или tdata, отправляете ссылки на посты, а бот доставляет медиафайлы обратно.

---

## Архитектура проекта

Проект работает по схеме двух клиентов внутри одного Python-процесса (Dual Client Architecture) на библиотеке Telethon:

```
+-------------------------------------------------------------+
|                     Docker-контейнер                        |
|                                                             |
|  [Бот-контроллер (Bot API)] <---> [MTProto Юзербот]         |
|              ^                           ^                  |
+--------------│---------------------------│------------------+
               │                           │
        Команды и диалог          Чтение закрытых постов
      в личном чате Telegram      и скачивание медиа (MTProto)
               │                           │
               v                           v
         Пользователь              Серверы Telegram
```

1. **Бот-контроллер (Bot API):** отвечает за диалог с владельцем (`OWNER_ID`), FSM-авторизацию, меню настроек и отправку стандартных файлов в чат.
2. **MTProto Юзербот (Telethon):** работает параллельно. Использует права вашего аккаунта (основного или твинка), получает доступ к закрытым каналам, где вы состоите, и забирает сырые фрагменты медиа напрямую из CDN Telegram в обход `noforwards`.

## Правила доставки файлов и атомарность

1. **Файлы до 50 МБ:**
   * Отправляются ботом прямо в диалог с ботом.
2. **Файлы свыше 50 МБ (до 2 ГБ, с Premium до 4 ГБ):**
   * Обходят 50 МБ лимит Bot API: юзербот отправляет их напрямую в выбранное хранилище.
3. **Правило атомарности поста/альбома:**
   * Если в посте или медиагруппе хотя бы один файл превышает 50 МБ (или отправка через бота завершилась ошибкой), **все файлы этого сообщения отправляются вместе в выбранное хранилище** через юзербота. Альбом никогда не разрывается на части.
4. **Варианты хранилища (настраиваются в `/settings`):**
   * **Вариант А (по умолчанию):** Личные сообщения / «Избранное» (Saved Messages) от твинка.
   * **Вариант Б:** Приватный канал или группа-хранилище (вы задаете `TARGET_CHAT_ID` кнопкой в боте).
5. **Автоматическая локальная очистка:**
   * Сразу после завершения отправки всех файлов сообщения временные файлы и папка задачи на диске сервера безвозвратно удаляются.

## Защита от сброса сессий (TgActor / tg-invite-machine)

В проекте реализованы практики, предотвращающие бан и сброс сессий (`AUTH_KEY_DUPLICATED`):

* **Безопасный импорт Tdata через `opentele2`:** Вызывается метод `ToTelethon(flag=CreateNewSession)`. Скрипт не копирует рабочий ключ у Desktop, а делает вторичную авторизацию, создавая независимый `auth_key`. Оригинальный Telegram Desktop продолжает работать без сбросов.
* **Эмуляция официального десктопа:** Юзербот передает параметры официального Telegram Desktop (Windows 11 / macOS, официальные номера версий), исключая подозрения на ботовую активность со стороны MTProto.
* **Формат `StringSession`:** Сессия хранится в виде строки в `sessions/userbot.session`, что защищает от блокировок SQLite-файлов при остановке контейнера.

## Быстрый старт

### 1. Подготовка конфигурации

Клонируйте проект и создайте файл `.env`:

```bash
cp .env.example .env
nano .env
```

Заполните обязательные переменные:
* `BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather).
* `OWNER_ID` — ваш числовой Telegram ID (можно узнать через [@userinfobot](https://t.me/userinfobot)).
* `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` — ключи с [my.telegram.org](https://my.telegram.org) (по умолчанию используются официальные desktop-ключи).

### 2. Запуск через Docker Compose

```bash
docker compose up -d --build
```

Посмотреть логи сервиса:
```bash
docker compose logs -f
```

## Авторизация юзербота (три способа)

### Способ 1. Авторизация по QR-коду (основной и рекомендуемый)
1. Отправьте боту команду `/start` и нажмите «Вход по QR-коду».
2. Бот пришлет изображение с QR-кодом.
3. Откройте мобильный клиент Telegram: **Настройки → Устройства → Подключить устройство**.
4. Наведите камеру на QR-код. Авторизация завершится за 2 секунды без ввода номеров и СМС.

### Способ 2. Авторизация по номеру телефона (с интерактивной клавиатурой)
1. Нажмите «Вход по номеру телефона» в меню `/start` или `/settings`.
2. Введите номер телефона в международном формате (например, `+79991234567`).
3. Для ввода кода используйте интерактивные кнопки на клавиатуре бота (это защищает код от мгновенного сжигания фильтрами Telegram).
4. Если на аккаунте включен 2FA — введите облачный пароль по запросу бота.

### Способ 3. Авторизация через Tdata
1. Положите папку `tdata` (или `.zip` архив с ней) в каталог `./tdata_input/`.
2. Нажмите кнопку «Импорт Tdata из папки».
3. Бот конвертирует сессию через `opentele2` (`CreateNewSession`). Если установлен 2FA, бот запросит пароль в чате.

## Команды и управление

* `/start` — проверка статуса сервиса, информация о подключенном юзерботе и мастер первого запуска.
* `/settings` — интерактивное меню переключения режимов доставки:
  * Переключение места доставки тяжелых файлов (`ЛС / Избранное` ↔ `Канал / Группа`).
  * Установка ID целевого канала/группы (`TARGET_CHAT_ID`).
  * Кнопка повторного сканирования папки `./tdata_input`.
  * Сброс текущей сессии юзербота.
* **Отправка ссылки:** просто отправьте боту ссылку вида:
  * `https://t.me/c/1234567890/42` (закрытый канал/чат)
  * `https://t.me/channel_name/42` (публичный канал)

## Структура репозитория

```text
telegraber/
├── docker-compose.yml       # Конфигурация Docker Compose
├── Dockerfile               # Python 3.12-slim образ с компиляцией cryptg
├── requirements.txt         # Зависимости проекта
├── .env.example             # Шаблон конфигурации
├── README.md                # Документация проекта
├── app/
│   ├── __init__.py
│   ├── config.py            # Настройки Pydantic, профили устройств, сохранение параметров
│   ├── session_manager.py   # Безопасный импорт tdata (opentele2), хранение StringSession
│   ├── userbot.py           # MTProto клиент Telethon: парсинг, скачивание, альбомы, отправка
│   ├── bot.py               # Бот-контроллер: меню /settings, FSM-авторизация, атомарная доставка
│   └── main.py              # Точка входа, оркестрация клиентов, graceful shutdown
├── sessions/                # Том постоянного хранения сессий и настроек рантайма
├── downloads/               # Временная папка скачивания (очищается автоматически)
└── tdata_input/             # Том для tdata (монтируется в режиме read-only)
```
